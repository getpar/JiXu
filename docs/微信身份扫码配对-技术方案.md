# 微信身份 + 扫码配对（方案B）技术方案

> 版本：v1.2.0 设计稿 · 2026-11-11
> 目标：三端（Windows 桌面 / 微信小程序 / Android）不再手输 12 位同步码。
> 原则：现有同步引擎（ownerId / 笔数配对 / 删除凭证 / 待办快照）**完全不动**，只换“身份入口”。

---

## 1. 身份模型

- `ownerId`（12 位大写字母数字）仍然是**账本唯一标识**，云端每条记录继续按 `ownerId` 隔离。
- 新增 **微信身份 ↔ ownerId** 映射：
  - 小程序启动时调用云函数 `account`，用微信 `OPENID` 换取本用户的 `ownerId`；
  - 首次使用时把本机现有的同步码“认领”到当前微信身份上（老账本无缝保留）；
  - 以后换手机/重装小程序，用同一个微信打开，云函数返回同一个 `ownerId`，账本自动回来。
- 电脑端 / 安卓端不直接对接微信登录（那需要微信开放平台企业认证），而是通过**小程序授权配对**拿到同一个 `ownerId`。

---

## 2. 云函数 `account`

目录：`miniapp/cloudfunctions/account/`

### 2.1 调用方式

小程序内：

```js
wx.cloud.callFunction({
  name: 'account',
  data: { action: 'resolve', claimOwnerId: '<本机现有同步码，可空>' }
})
```

### 2.2 返回

```json
{ "ok": true, "ownerId": "ABCD2345EFGH", "isNew": true }
```

失败：

```json
{ "ok": false, "code": "OWNER_TAKEN", "error": "这个账本已绑定其他微信" }
```

错误码：`NO_OPENID` / `OWNER_TAKEN` / `BAD_OWNER` / `BAD_ACTION` / `INTERNAL`。

### 2.2.1 高级动作（v1.2.0 小程序「高级（备用同步码）」用）

- `{ action: 'bind', ownerId: '<12位码>' }`：把当前微信直接绑到指定账本（加入别人账本 / 换码后同步映射）。
- `{ action: 'reset' }`：给当前微信换一个新的账本码（清空本机数据后使用），返回 `{ ok:true, ownerId }`。
- `{ action: 'createMiniCode', pairToken }`：安卓 App 通过 CloudBase HTTP API 调用，生成 `pages/pair/index` 的微信小程序码，返回 `{ ok:true, imageBase64 }`；不需要 openid。
- 普通用户永远不需要手动调用这些动作；`resolve` 会自动完成首次认领。

### 2.3 行为

1. `cloud.getWXContext().OPENID` 取当前微信用户；取不到直接返回 `NO_OPENID`。
2. 确保集合 `accounts` 存在（`db.createCollection('accounts')`，已存在则忽略）。
3. 查询 `accounts.where({ openid })`：
   - 有记录 → 直接返回它的 `ownerId`（`isNew: false`）；
   - 没有记录：
     - `claimOwnerId` 合法且未被其他 openid 占用 → 用它；
     - `claimOwnerId` 已被其他 openid 占用 → `OWNER_TAKEN`；
     - 没传/不合法 → 服务端生成新的 12 位同步码。
4. 写入 `accounts` 文档：

```json
{
  "_id": "<sha256(openid) 前 32 位>",
  "openid": "<微信 openid，仅服务端可见>",
  "ownerId": "ABCD2345EFGH",
  "createdAt": 1760000000000,
  "updatedAt": 1760000000000
}
```

> `accounts` 集合权限建议「仅创建者可读写」或「仅管理端可读写」。客户端从不直接读它，只有云函数（管理员权限）访问。

---

## 3. 配对协议（复用现有 `records` 集合，零新增集合）

所有配对文档都**不带 `ownerId` 字段**（`ownerId` 是同步引擎的户标识过滤字段）。配对回执/邀请里要传递的账本码统一叫 **`targetOwnerId`**，因此同步引擎的 `listAll(ownerId)` 永远不会拉到它们，不会污染账本。

### 3.1 电脑端发起配对（电脑显示二维码 → 手机小程序扫）

电脑端创建：

```json
{
  "kind": "pair_req",
  "pairingId": "<32 位随机 hex>",
  "shortCode": "<6 位数字>",
  "deviceType": "desktop",
  "deviceName": "Windows 电脑",
  "createdAt": 1760000000000,
  "expiresAt": 1760000300000
}
```

二维码内容（手机 `Taro.scanCode` 扫到的字符串）：

```json
{"v":1,"t":"jixu-pair","pid":"<pairingId>","code":"<shortCode>","name":"Windows 电脑"}
```

手机小程序扫码（或手动输入 6 位 `shortCode`）后：

1. 按 `pairingId`（或 `shortCode` + `kind=pair_req` 取最新一条）找到请求；
2. 校验未过期（`expiresAt > Date.now()`）；
3. 创建回执：

```json
{
  "kind": "pair_ack",
  "pairingId": "<同一个 pairingId>",
  "targetOwnerId": "<手机当前 ownerId>",
  "createdAt": 1760000050000,
  "expiresAt": 1760000300000
}
```

电脑端每 1.5 秒查询一次：

```js
db.collection('records')
  .where({ kind: 'pair_ack', pairingId })
  .limit(1)
  .get()
```

拿到 `ownerId` 后：

- `setOwnerId(ownerId)` 保存到本机；
- 立即执行一次强制同步；
- 删除自己创建的 `pair_req` 文档（失败可忽略）；
- 弹“已绑定微信账本”。

### 3.2 安卓端配对（安卓显示小程序码 → 保存到相册 → 微信扫一扫）

安卓端创建配对请求（带短 token，供生成小程序码场景值）：

```json
{
  "kind": "pair_req",
  "pairingId": "<32 位随机 hex>",
  "pairToken": "<16 位随机 hex>",
  "deviceType": "android",
  "deviceName": "安卓手机",
  "createdAt": 1760000000000,
  "expiresAt": 1760000300000
}
```

安卓调用云函数 `account`：

```json
{ "action": "createMiniCode", "pairToken": "<16 位 token>" }
```

云函数调用微信 `wxacode.getUnlimited` 生成小程序码（`page: 'pages/pair/index'`，`scene: 'p=<pairToken>'`），返回：

```json
{ "ok": true, "imageBase64": "<PNG base64>" }
```

安卓把小程序码显示出来，用户**保存到相册** → 打开微信「扫一扫」→ 从相册选图 → 微信打开计序小程序 `pages/pair/index?scene=p%3D<token>`。

小程序配对页解析 `scene`，按 `pairToken` 找到 `pair_req`，创建回执：

```json
{
  "kind": "pair_ack",
  "pairingId": "<同一个 pairingId>",
  "targetOwnerId": "<手机当前 ownerId>",
  "createdAt": 1760000050000,
  "expiresAt": 1760000300000
}
```

安卓每 1.5 秒查询 `kind='pair_ack'` + `pairingId`，校验 `targetOwnerId` 和有效期后保存并强制同步。

> 因为安卓 App 和小程序通常在同一台手机上，无法直接扫自己的屏幕，所以需要「保存到相册 → 微信扫一扫 → 从相册选择」这一步；如果有第二台手机/平板，可以直接扫。

### 3.3 安卓端备用配对（6 位一次性配对码）

手机小程序创建：

```json
{
  "kind": "pair_invite",
  "shortCode": "<6 位数字>",
  "targetOwnerId": "<手机当前 ownerId>",
  "deviceType": "android",
  "createdAt": 1760000000000,
  "expiresAt": 1760000300000
}
```

安卓端在「云同步」弹窗输入 6 位码后：

```js
query: { kind: 'pair_invite', shortCode: '123456' }
```

校验 `expiresAt > now`、`ownerId` 合法后保存并强制同步。

### 3.3 有效期

- 所有配对请求 / 邀请 / 回执默认 **5 分钟** 过期。
- 二维码和 6 位码都是**一次性**的；绑定成功后电脑端会删掉自己的请求文档。

## 5. 兼容与回退

- 云函数未部署 / 未连真云：小程序继续用本机同步码，所有旧功能不变。
- 老用户升级：小程序第一次调用 `account` 时把当前本机同步码传上去认领，历史账本不动。
- 电脑/安卓端旧同步码输入保留在「高级（备用）」里，扫码失败可手动输码。
- 所有配对文档不带 `ownerId`，同步引擎完全无感。

---

## 6. 安全边界（如实说明）

- 本方案解决的是“方便 + 账号找回”，不是“绝对防盗”。
- 现有 `records` 集合权限是「所有用户可读，仅创建者可写」，拿到环境 ID 的人理论上能读全量数据；配对文档 `pair_req/pair_ack/pair_invite` 也复用这个集合，同样只能靠环境 ID 不公开 + 配对码 5 分钟过期来降低风险。这是既有架构的边界，本次不改变；**不要把 CloudBase 环境 ID 发给不信任的人**。
- 真正的“只有本人能读”需要把读取也收到云函数/自定义登录后面，列为后续加固项。
- 配对码 5 分钟过期、一次性；二维码只在用户主动点“绑定”时展示。

## 7. 验收清单

1. 小程序冷启动：`account` 云函数返回同一个 ownerId；清缓存重进仍是同一个。
2. 老同步码账本认领后，历史账单/待办/周期/存钱罐都能正常同步。
3. 桌面端生成二维码 → 手机小程序扫码 → 电脑自动绑定并同步。
4. 手机小程序生成 6 位码 → 安卓输入 → 安卓自动绑定并同步。
5. 三端同时在线，新增/删除/编辑一笔，另外两端同步后一致。
6. 云函数不可用时，小程序仍可用同步码正常工作。
7. 桌面 `tsc` + `electron-vite build`、小程序 `build:weapp`、安卓单测 + `assembleDebug` 全部通过。
8. 云函数纯逻辑：`npm run verify:account`（6 项：首次认领 / 重复进入 / 抢码拒绝 / bind / reset / 无 openid 拒绝）全部通过。
