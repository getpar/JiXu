# 计序 · Android 原生版执行计划（交给 DeepSeek 分阶段开发）

> 配套：[`开发文档.md`](./开发文档.md)（全部技术细节）。本文件告诉你**按什么顺序做、每步怎么跟 DeepSeek 说、怎么判断它做对了**。
> 原则：先做「算账不出错」的底层（P1~P4，全靠自动测试把关），再做界面（P5~P8），最后三端互通验收和发包（P9）。底层不过关，界面做得再好看也会对不上账。

---

## 一、开工前准备（你来做，只做一次）

1. **备份**：把整个项目文件夹复制一份，或让 DeepSeek 先做一次 git 提交。
2. **装 Android Studio**（最新稳定版）：第一次打开按向导点「下一步」，它会自动装好安卓开发包（SDK）和 JDK。
3. **准备一台测试手机**（推荐真机）：设置 → 关于手机 → 连点「版本号」7 次打开开发者模式 → 开发者选项里打开「USB 调试」→ 数据线连电脑 → 手机弹窗点「允许」。没有闲置手机就用 Android Studio 自带的模拟器。
4. **DeepSeek 的工作环境**：需要能读写本项目文件、能在终端运行命令（例如在 VS Code / Cursor / Trae 等编辑器里接入 DeepSeek 模型）。只能聊天、不能运行命令的方式做不了这个项目。
5. 准备一个**测试用同步码**：P4 和 P9 用。在小程序「云同步」里点「换新码」生成一个新码记下来，测试完再「加入」回你原来的码。**测试期间别用真实账本的码。**

## 五、常见卡点与对策

| 现象 | 处理 |
|---|---|
| P2 回放卡在少数几条 | 让 DeepSeek 打印那条录像的场景名和第一处不一致的调用，对照 cloudCore.ts 同一段逐行比；最常见是金额转字符串（§6.3）、Map 迭代顺序、倒序遍历 |
| 同步报 401 | 看 §5.2 刷新逻辑；换过云环境要清登录态 |
| 同步报 `DATABASE_PERMISSION_DENIED` | 云开发控制台「权限控制 → 策略管理」检查匿名角色的 HTTP API 权限（§5.1） |
| Gradle 下载依赖很慢 | 让 DeepSeek 给你列加速方案再选（属于工具选择，按规则要你拍板） |
| 提醒不准时 | 手机设置里给「计序」关闭省电限制、允许自启动/后台运行（各品牌叫法不同） |
| DeepSeek 想换库、换方案 | 按规则它必须先列方案给你选；不懂就回它「用你推荐的，但说清楚风险」 |
| 小程序同步逻辑以后改了 | 在 miniapp 目录运行 `npm run export:android` 重新生成金标准，再让 DeepSeek 重跑 P1/P2 测试 |
