# 需求评估 02 · 存钱罐（独立小账本）

> 评估日期：2026-11-11
> 对应需求：你本次列出的第 1 条 —— 每个月发工资后取出一部分现金存起来（例如 500 元），记工资时目前会少记这 500 元，但希望 App 能帮忙记住，并能直白地看到一共存了多少钱。
> 补充确认（2026-11-11）：
> ① **首页不显示存钱数额**；
> ② **存钱功能完全独立，不参照、不接入现有记账功能**；
> ③ **原有「本月结余」计算不加入存钱金额**——首页结余 5000 就还是 5000，存了 500 只在存钱罐里单独显示。
> 评估结论：**技术上完全可行。推荐做成一个完全独立的「存钱罐」小账本：不改变现有收入、支出、结余、预算和统计，首页只保留不带金额的入口，所有存款数字只在存钱罐页面看。**
> 当前状态：**已拍板：数据保存方式 = 方案 B 独立云同步（2026-11-11）；代码已按该方案实现，待真机验收。**
> 关联文档：[`开发文档.md`](./开发文档.md)、[`执行计划.md`](./执行计划.md)、[`需求评估-01-自动记账.md`](./需求评估-01-自动记账.md)

## 0. 先看结论（30 秒版）

1. **能做，而且不需要改现有账本逻辑。** 存钱是另一个独立的小账本，和「收入 / 支出 / 结余 / 预算 / 统计」都不发生关系。
2. **用你的例子说：** 首页本月结余显示 ¥5,000，你另外存了 ¥500，首页仍然显示 ¥5,000；存钱罐页面单独显示「已存 ¥500」。
3. **记工资方式完全不变：** 你原来怎么记就怎么记（记全额、或自己先减掉存钱再记，都照旧）；存钱功能不读取、不修改那笔收入，也不会自动生成存款记录。存钱需要你在存钱罐页面单独记一笔。
4. **首页不显示金额：** 不新增存钱罐卡片、不在结余区域显示存款数字；首页只保留一个不带金额的「存钱」入口（是否保留这个入口也可以再定）。
5. **存钱罐页面独立：** 当前存款总额、本月存入、累计存入/取出、每一笔存入/取出记录，都在这个页面里看。
6. **数据保存：已选方案 B 独立云同步。** 存钱记录存进腾讯云一个**独立的新集合 `savings`**（不是现有 `records` 账单集合），换手机/重装后能恢复；现有账本的云同步完全不受影响。
7. **工作量：** 按方案 B（本地存钱罐 + 独立云同步）约 **5~7 个开发工作日**。不碰现有账单、统计、预算和现有云同步。

## 2. 这个需求到底要解决什么

### 2.1 你的实际场景（按你确认的口径）

| 项目 | 金额 | 怎么处理 |
|---|---:|---|
| 工资到账 | ¥8,000 | 照旧按你原来的方式记收入（示例记 8,000；如果你习惯先减 500 记 7,500，也照旧） |
| 当月支出 | ¥3,000 | 照旧记支出 |
| 首页「本月结余」 | ¥5,000 | **仍然显示 ¥5,000，不扣存钱** |
| 另外存现金 | ¥500 | 单独在「存钱罐」页面记一笔存款 |
| 存钱罐页面 | ¥500 | 单独显示当前存款总额，首页不显示 |
| 以后累计存钱 | 例如 ¥3,500 | 存钱罐页面显示累计金额和每一笔记录 |

### 2.2 加了功能后的理想流程

| 步骤 | 你会看到/操作 |
|---|---|
| 1. 发工资 | 工资到账 ¥8,000 |
| 2. 去存现金 | 取出 ¥500，放好 |
| 3. 打开存钱罐 | 点「存一笔」，金额 500，日期今天，备注可选 |
| 4. 存钱罐页面 | 当前存款总额 +500，历史里多一笔「11-11 · 存入 ¥500」 |
| 5. 首页 | 本月结余仍是原来的数字（例如 ¥5,000），**不显示存款金额** |
| 6. 平时查看 | 进入存钱罐页面，看总额和每笔记录 |

**关键：存钱不是在记账，也不是在转钱进某个账户；它只是「另外记一本小账」，用来提醒自己存了多少现金。**

### 2.3 这个功能明确「不做什么」

- **不把存钱算成支出**：不改「本月支出」。
- **不把存钱算成收入**：不改「本月收入」。
- **不改变「本月结余」公式**：结余仍然只按收入 − 支出算，不扣存款。
- **不改变工资录入**：不做「工资 8000 其中存 500」的拆分，不自动生成存款记录。
- **不影响预算、统计、饼图、月度报告、TOP3**：这些功能完全不动。
- **不碰现有云同步账本**：存款记录不进入 `records` 表，也不进入现有云同步通道。
- **不是银行账户管理**：首版只做「一个现金存钱罐」，不做银行卡、理财、利息、负债等复杂资产体系。

## 3. 已确认的记账边界（这一版就按这个来）

你刚才已经明确：

1. **存钱功能是单独的**，不参照之前的记账功能。
2. **之前的结余计算不加入存钱金额**。
3. 首页例子：本月结余 5000，存了 500，首页仍然是 5000。

所以本方案把存钱做成**一个独立模块**（不必做成第五个底部页签，先做一个二级页面即可）：

| 模块 | 是否与存钱有关 |
|---|---|
| 记一笔（收入/支出） | ❌ 完全不变 |
| 本月收入 | ❌ 不加入存款 |
| 本月支出 | ❌ 不加入存款 |
| 本月结余 | ❌ 不扣存款 |
| 预算 | ❌ 不占用预算 |
| 统计（饼图/柱状图/趋势/报告） | ❌ 不统计存款 |
| 账单列表 | ❌ 不显示存款记录 |
| 回收站 | ❌ 不混入存款记录 |
| 云同步账本 | ❌ 不进入现有 `records` 同步通道 |
| 存钱罐页面 | ✅ 只在这里显示存款总额和明细 |

**一句话：存钱功能自己玩自己的，不碰原来的任何数字。**

## 4. 实现方式三选一（已选方案 B）

产品形态已经确定为「独立存钱罐」，数据保存方式你已选择 **方案 B：独立云同步**。下面是三种方式的完整对比，方便你以后回看；实际按 B 执行。

### 方案 A：本机独立存钱罐（备选）

**通俗解释**：在手机里单独建一本「存钱账本」，只存在这台手机上。和原来的账单数据库完全分开，互不影响。

**优势：**
- 最快、最简单，约 3~4 个开发工作日。
- 完全不影响现有记账、统计、预算和云同步。
- 不需要新建云数据库集合，不需要额外后台配置。
- 没有「存款记录混进账单」的风险。

**劣势：**
- 卸载 App、换手机、清除应用数据后，存钱记录会丢失（除非手机系统自带备份）。
- 电脑端、小程序看不到存钱记录。

**适合：** 先在手机上把功能用起来，确认自己真的会长期记，再决定要不要加云同步。

---

### 方案 B：独立存钱罐 + 独立云同步（已选）

**通俗解释**：还是单独一本「存钱账本」，但把它存到腾讯云的一个**新集合**里（比如叫 `savings`），不放进原来的 `records` 账单集合。换手机后重新登录，存钱记录也能回来。

**优势：**
- 数据安全，换手机/重装不丢。
- 和现有账单云同步完全隔离，不会影响原来的账本。
- 以后电脑端/小程序想看存钱罐，也有数据基础。

**劣势：**
- 要在腾讯云控制台新建 `savings` 集合并设置权限（一次性操作）。
- 多写一套独立的同步逻辑，约多 2~3 天。
- 维护成本略高。

**适合：** 你希望存钱记录长期保存、换手机不丢，且愿意多做一次云配置。

---

### 方案 C：借用现有账单表 / 现有同步通道（不推荐）

**通俗解释**：把存钱记录伪装成一笔特殊账单，塞进现有的 `records` 表，跟着现有云同步一起走。

**优势：**
- 看起来改动少，不用新建表。
- 能自动跟着现有云同步走。

**劣势：**
- 违背你「存钱功能单独、不参照之前功能」的要求。
- 现有账单表、统计、导出、回收站都要额外过滤，稍不注意就会把存款算进支出或结余。
- 旧版本 App、电脑端、小程序可能把存款当普通账单显示。
- 一旦以后改账单同步逻辑，存钱功能会被牵连。

**适合：** 不推荐。省一点开发时间，换来长期耦合和出错风险，不划算。

|---|---|---|---|

**🎯 你已拍板：方案 B（独立云同步）。**
- 存钱记录存进独立的 `savings` 云集合，换手机、重装后可以恢复。
- 现有 `records` 账单和它的云同步完全不碰。
- 实际开发可以按「先本地表和页面 → 再接独立云同步」的顺序做；即使云集合还没建好，本地存钱也能先用，只是暂时不能跨手机恢复。

> 注意：即使选 B，也不会碰现有 `records` 账单和它的云同步；`savings` 是另一套独立数据。

## 5. 推荐方案长什么样（产品设计）

### 5.1 首页：只放一个不带金额的「存钱」入口

按你的要求，**首页不显示存款总额、不显示本月存入、不显示任何存款数字**。

入口建议放在首页「本月支出」卡下方，做成一行独立入口：

- 只显示「存钱罐」和「独立小账本，不计入本月结余」；
- **不带金额、不带余额、不带本月存入**；
- 点击后进入存钱罐页面，所有金额只在那个页面里看；
- 即使还没有存过钱，入口也正常显示，不显示 0，也不显示「未设置」之类的金额提示。

**不做首页存钱罐卡片。** 首页原有的「本月支出 / 收入 / 结余」区域完全不改，不混入任何存款数字。

> 如果你连这个「存钱」入口都不想放在首页，也可以改成从「记一笔」页面或页脚进入——这个可以在开工前再定。

### 5.2 存钱罐页面

**顶部：**
- 标题「存钱罐」
- 大数字：当前存款总额
- 小字：`累计存入 ¥2,000 · 累计取出 ¥500 · 本月存入 ¥500`

**操作按钮：**
- `+ 存一笔`（主按钮）
- `− 取一笔`（次要按钮；总额为 0 时置灰或隐藏）

**历史记录：**
- 按月份分组（如「2026 年 11 月」）
- 每行：`11-11 · 现金存款 · 备注`，右侧 `+¥500`（存入）或 `−¥500`（取出）
- 空状态：`还没有记录，点「存一笔」开始吧`
- 底部可折叠「已删除 (N)」：误删的存款记录可以恢复

**「存一笔」弹窗：**
- 金额（¥，数字键盘，沿用现有金额校验规则）
- 日期（默认今天，可选过去日期，方便补记以前的存款）
- 备注（可选，例如「给妈妈保管」「放在抽屉」）
- 按钮：`取消` / `保存`

**「取一笔」弹窗：**
- 金额不能大于当前存款总额，否则提示「取钱金额不能大于存款总额」
- 日期、备注可选
- 确认后存款总额减少

### 5.3 记一笔：完全不变

- 收入照旧按你原来的方式记（记全额，或自己先减存钱再记，都行）。
- 支出照旧记。
- 不新增「其中存现金」字段，不做工资拆分。
- 存钱只能去「存钱罐」页面单独记。

### 5.4 统计与预算：完全不变

- 本月支出、本月收入、本月结余：不包含存款。
- 预算：不受存款影响。
- 饼图、柱状图、每日趋势、月度报告、TOP3：全部不包含存款。
- 存钱罐页面自己统计：累计存入、累计取出、当前余额、本月存入。

### 5.5 编辑、删除、撤销

- 存钱罐页面的每一笔可以编辑金额/日期/备注，也可以删除。
- 删除为「软删除」，可在「已删除」里恢复，避免误删。
- 存钱记录和普通账单回收站完全分开，不混在一起。
- 存钱操作不出现「5 秒撤销条」；用存钱罐页面自己的「已删除」恢复即可（也可以加一个删除前确认）。

### 5.6 数据安全与备份（已选方案 B）

- 存钱记录存本地 `savings` 表，同时同步到独立的 `savings` 云集合；换手机/重装后重新加入同一个同步码，存钱记录能回来。
- 现有账单的 `records` 云集合和同步逻辑完全不动，两套数据互不干扰。
- 如果云端暂时不可用（没网、集合未创建、权限未配置），存钱仍可正常记在本机；页面右上角显示「云同步：已同步 / 同步中 / 仅本机」状态，等云端恢复后自动补传。
- 存钱罐页面建议加一个「导出存钱记录」按钮（Excel/CSV），作为额外的本地备份手段。

## 6. 数据怎么存（通俗版）

新增一张独立的小表 `savings`，只存存钱记录，不碰现有 `records` 账单表。

每条存钱记录包含：

| 字段 | 内容 |
|---|---|
| 类型 | `in`（存入）/ `out`（取出） |
| 金额 | 正数，元 |
| 日期 | `YYYY-MM-DD` |
| 备注 | 可选 |
| 创建时间 | 记录提交时刻（用于同一天排序） |
| 删除标记 | 软删除用 |

存款总额 = 所有「存入」金额之和 − 所有「取出」金额之和。

因为你选了**独立云同步**，每次存/取/编辑/删除还会向腾讯云的独立 `savings` 集合追加一条「存钱专用」的同步快照；它和现有 `records` 账单集合互不相干，换手机后重新加入同一个同步码就能恢复。

这样做的四个好处：
1. **完全独立**：现有账单表、统计、预算、云同步都不需要改。
2. **不会算错**：存款永远进不了「收入/支出/结余」的计算。
3. **换手机不丢**：存钱数据在自己的云集合里，重装后能拉回来。
4. **以后好扩展**：如果要做「多个存钱罐」「存钱目标」，可以在这张表上继续加字段。

## 7. 边界情况清单

| 场景 | 期望行为 |
|---|---|
| 首页本月结余 5000，另存 500 | 首页仍显示 5000；存钱罐页面显示 500 |
| 工资 8000，存 500 | 账单里的收入保持你原来记录的数字（例如 8000 或 7500），存钱罐单独 +500 |
| 存钱金额为 0 | 提示金额不能为 0（或不允许保存） |
| 取钱金额 > 当前存款总额 | 不允许保存，提示「取钱金额不能大于存款总额」 |
| 同一天存两笔 500 | 两笔都保留，总额 +1000 |
| 编辑一笔存款 | 总额按修改后的金额重算 |
| 删除一笔存款 | 总额减少；可在「已删除」里恢复 |
| 存入后又取出，余额归零 | 显示 ¥0，不显示负数 |
| 换手机/重装（方案 A） | 存钱记录不会自动回来（可提前导出备份） |
| 换手机/重装（方案 B） | 重新连接后存钱记录回来 |
| 旧版本 App | 看不到存钱入口，但不影响原有账单使用 |
| 清除现有账单数据 | 存钱记录是否一起清除需要明确：建议「清除所有数据」时一并清除存钱记录，并给二次确认 |
| 存款记录很多（几年） | 分页/分批渲染，沿用账单页的懒加载方式 |

## 8. 对现有功能的影响

## 附录 A · 技术设计（给开发看，非技术用户可以跳过）

### A.1 数据模型（独立表）

新增 `savings` 表，与现有 `records` 完全分开：

| 列 | 类型 | 说明 |
|---|---|---|
| `id` | TEXT 主键 | 本机毫秒时间戳字符串，同毫秒顺延 1ms |
| `direction` | TEXT | `in`（存入）/ `out`（取出） |
| `amount` | REAL | 正数，元 |
| `date` | TEXT | `YYYY-MM-DD` |
| `note` | TEXT | 备注，默认 `''` |
| `created_at` | INTEGER | 提交时刻毫秒 |
| `deleted` | INTEGER | 0 正常 / 1 已删除 |
| `revive_count` | INTEGER | 恢复次数（软删除恢复用） |
| `updated_at` | INTEGER | 仅方案 B（云同步）需要 |

索引：`(deleted, date)`。

### A.2 Room 迁移

- `AppDatabase` 从 `version = 1` 升到 `version = 2`。

### A.5 独立云同步（已选方案 B，必做）

**云集合准备（上线前一次性配置）：**
- 在 CloudBase 控制台新建集合 `savings`。
- 权限设置为「所有用户可读，仅创建者可写」（与现有 `records` 集合一致；跨设备同同步码才能读回）。
- 不需要云函数。

**本地表字段：**

| 列 | 类型 | 说明 |
|---|---|---|
| `id` | TEXT 主键 | 本机生成的稳定 id，跨端用它识别同一条存款 |
| `direction` | TEXT | `in` / `out` |
| `amount` | REAL | 正数 |
| `date` | TEXT | `YYYY-MM-DD` |
| `note` | TEXT | 备注 |
| `created_at` | INTEGER | 提交时刻毫秒 |
| `updated_at` | INTEGER | 每次保存/编辑/删除时更新（同步比较用） |
| `deleted` | INTEGER | 0 正常 / 1 已删除 |
| `revive_count` | INTEGER | 恢复次数 |

**云端文档（追加式快照，不覆盖旧文档）：**

```jsonc
{
  "kind": "savings",
  "entityId": "<本地 id>",
  "ownerId": "<同步码>",
  "updatedAt": 1793700000000,
  "source": "android:<8位设备标识>",
  "data": {
    "id": "<本地 id>",
    "direction": "in",
    "amount": 500,
    "date": "2026-11-11",
    "note": "现金",
    "createdAt": 1793700000000,
    "deleted": false,
    "reviveCount": 0
  }
}
```

**同步规则（LWW 快照）：**
1. 打开存钱罐页、App 冷启动、以及存/取/编辑/删除后触发一次独立同步。
2. `listAll(ownerId)` 拉取 `savings` 集合本户全部快照，按 `entityId` 分组，取 `updatedAt` 最大的一条。
3. 云端快照比本地新 → 覆盖本地那一笔（含删除标记）。
4. 本地比云端新或云端不存在 → 追加一条新快照上云。
5. 删除 = 生成一条 `deleted: true` 的新快照，不物理删云端文档；恢复 = 生成 `deleted: false` 且 `reviveCount+1` 的新快照。
6. 网络失败只影响本次同步，本地操作不阻塞，下次进入存钱罐或下次写操作时自动补传。

**代码接入点：**
- `CloudEnv.documentsUrl(envId, collection)` 增加集合名参数，默认 `records`，传 `savings` 时访问独立集合。
- `AppContainer` 新增第二个 `CloudBaseCollection`（集合名 `savings`）和独立的 `SavingsSyncManager`；不要复用现有 `SyncManager` 的 `SyncDeps`（避免两条账本互相影响）。
- 现有 `SyncEngine`、`SyncManager`、`records` 云集合一行不改。

**同步状态提示：**
- 存钱罐页面右上角显示「已同步 / 同步中 / 仅本机（云端未配置）」；错误只提示、不阻塞记账。

## 附录 B · 为什么不再考虑「复用账单表」

你确认「存钱功能单独、不参照之前功能」后，复用 `records` 表已经不合适：

| 问题 | 复用账单表的风险 |
|---|---|
| 统计口径 | 必须在所有统计/导出/页面里加过滤，漏一处就出错 |
| 结余计算 | 需要确保存款永远不被算进收入/支出，维护成本高 |
| 云同步 | 存款会进入现有同步通道，旧版本 App 可能显示异常 |
| 需求边界 | 和「存钱独立」的要求相冲突 |

**独立 `savings` 表是最符合你这次要求的做法。**
