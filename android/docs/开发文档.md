## 0. 铁律（开工前必读，任何时候都优先于下文细节）

1. **参照实现优先级**：`miniapp/src/utils/cloudCore.ts`（同步引擎）＞ `money.ts`（金额）＞ `dates.ts`（日期）＞ `storage.ts`（本地读写语义）＞ `miniapp/src/pages/*`（界面与文案）。本文档与这些源码冲突时**以源码为准**，并在交付说明里指出冲突处。
2. **三端对账是生命线**：电脑、小程序、安卓读写同一个云数据库集合 `records`。同步引擎必须通过 `fixtures/sync-traces.json` 的 **55/55 次录像回放**，金额/日期等基础函数必须通过 `fixtures/golden-vectors.json` 的 **16 组金标准**。任何一条不过都不算完成，不许改测试去迁就实现。
3. **技术决策规则**（项目根 `AGENTS.md`）：本文档 §1、§3 已写明的选型照做；**没写明的**新库、新架构、新服务，必须先给负责人列 2-3 个方案（通俗语言 + 优劣 + 推荐），拿到选择后再动手。
4. **不动别的端**：不得修改 `miniapp/`、`desktop/` 下任何文件（负责人明确要求的除外）。安卓工程全部放在 `android/`。
5. **文案照搬**：界面中文文案沿用小程序原文（§8 标了出处），只在「微信 → 安卓」确实不同的地方改写。
6. **只存本机的数据与小程序一致**：预算、自定义分类、小票照片、外观偏好不上云。

## 4. 数据模型

### 4.1 Room 表（字段与小程序 `storage.ts` 一一对应；列名用 snake_case，Kotlin 属性用 camelCase）

**records（账单）**

| 列 | 类型 | 说明 |
|---|---|---|
| id | TEXT 主键 | 本机新记：毫秒时间戳字符串，同一毫秒顺延 1ms 保证不撞号（`storage.ts nextLocalId`）；从云端拉回：`cloud_<云端 _id>`（`cloudCore.ts cloudToLocal`）；编辑产生的新行：新的毫秒 id |
| type | TEXT | `expense` / `income` |
| amount | REAL | 元，Double。**累加一律先换算成「分」取整再加**（`sumAmounts` 语义，§7.1） |
| category_key / category_name | TEXT | 一级分类 |
| subcategory_key / subcategory_name | TEXT | 二级分类 |
| note | TEXT | 备注，默认 `''` |
| date | TEXT | `YYYY-MM-DD`（本机时区） |
| person | TEXT | 记录人，默认 `''` |
| created_at | INTEGER 可空 | 提交时刻毫秒；排序键见 §7.4 |
| photo | TEXT 可空 | 小票照片本机绝对路径，**不上云** |
| deleted | INTEGER | 0 正常 / 1 在回收站（软删） |
| revive_count | INTEGER | 被恢复过的次数（同步配额用，默认 0） |

索引：`(deleted, date)`、`(date, subcategory_key, type)`。

**todos（待办）**：`id` TEXT 主键、`title`、`cycle`（`daily|weekly|monthly|yearly|once`）、`next_date`、`time`（`HH:mm` 可空）、`is_active`、`amount`（可空）、`category_key/category_name/subcategory_key/subcategory_name`（可空）、`note`（可空）、`completed_dates`（TEXT，JSON 字符串数组）、`created_at`（TEXT，本端写 `YYYY-MM-DD`；电脑端推来的可能是别的格式，只展示不解析）、`updated_at` INTEGER、`deleted` INTEGER。

**recurring_bills（周期账单）**：`id` 主键、`type`、`amount`、四个分类列、`note`、`cycle`（`daily|weekly|monthly|yearly`）、`next_date`、`is_active`、`last_executed_for`（可空，执行回执）、`updated_at`、`deleted`。

**custom_categories（自定义分类，只存本机）**：`subcategory_key` 主键、`category_key`、`category_name`、`subcategory_name`、`seq`（插入顺序）。

**pending_purges（待上传注销凭条，离线不丢）**：`pid` 主键、`target_key`、`cancel_rec`、`cancel_tomb`、`cancel_rev`、`label`（可空）、`seq`（插入顺序，`getPending` 按它升序返回）。

### 4.3 待办 / 周期账单的云端快照 JSON（字段名必须一字不差）

同步时整条实体以 JSON 对象放进快照文档的 `data` 字段，三端互读。安卓**写出**时：键名用 camelCase，可选字段为空就**省略**（不要写 `null`）。安卓**读入**时要宽容：

```jsonc
// 待办（storage.ts interface Todo）
{ "id": "a_1793700000000_k3f9x2", "title": "交房租", "cycle": "monthly", "nextDate": "2026-12-01",
  "time": "09:00", "isActive": true, "amount": 2400, "categoryKey": "housing", "categoryName": "住房居家",
  "subcategoryKey": "rent", "subcategoryName": "房租/房贷", "note": "", "completedDates": ["2026-11-01"],
  "createdAt": "2026-10-20", "updatedAt": 1793700000000, "deleted": false }

// 周期账单（storage.ts interface RecurringBill）
{ "id": "a_1793700000000_q8w1zz", "type": "expense", "amount": 30, "categoryKey": "entertainment",
  "categoryName": "娱乐休闲", "subcategoryKey": "game", "subcategoryName": "游戏充值", "note": "会员",
  "cycle": "monthly", "nextDate": "2026-12-03", "isActive": true, "lastExecutedFor": "2026-11-03",
  "updatedAt": 1793700000000, "deleted": false }
```

读入宽容规则（电脑端推来的快照长这样）：`categoryName/subcategoryName` 为空串 → 按分类表补全（§7.3 `fillCatNames`）；`amount` 可能是 `0`；`time` 可能是 `''`；`completedDates` 缺失 → `[]`；`createdAt` 可能是任意字符串。

### 4.4 ID 规则

| 对象 | 格式 |
|---|---|
| 本机新账单 | 毫秒时间戳字符串，单调递增（同毫秒 +1） |
| 云端拉回的账单 | `cloud_` + 云端 `_id` |
| 安卓新建待办 / 周期账单 | `a_<毫秒>_<6 位 base36 随机>`（电脑端是 `d_…`，小程序是纯毫秒，三种可共存） |
| 注销凭条 pid | `p_<毫秒>_<8 位 base36 随机>`（同 `storage.ts purgeRecord`） |

## 5. 云端接入（CloudBase HTTP API）——以下请求/响应均于 2026-11-03 对真实环境实测

### 5.1 环境

| 项 | 值 |
|---|---|
| 默认环境 ID | `daily-notes-d3gaotrwyc09ff44a`（与 `miniapp/src/utils/cloud.ts`、电脑端一致）；可被「自定义云环境 ID」覆盖 |
| 网关 | `https://{envId}.api.tcloudbasegateway.com` |
| 集合 | `records`（账单、凭证、凭条、待办/周期快照全在这一个集合里，靠 `kind` 区分） |
| 集合权限 | 所有用户可读，仅创建者可读写（安卓只做**读**和**新增**，从不改/删别人的文档） |
| 控制台前置 | 匿名登录已开启；目前无需额外配置。若将来报 `DATABASE_PERMISSION_DENIED`：云开发控制台 →「权限控制 → 策略管理」检查匿名角色的文档型数据库 HTTP API 权限 |
| 官方文档 | 匿名登录 `docs.cloudbase.net/http-api/auth/auth-sign-in-anonymously`；刷新 `…/http-api/auth/auth-grant-token`；数据库 `…/http-api/nosql/nosql-restful-api`（OpenAPI：`docs.cloudbase.net/openapi/nosql.v1.openapi.yaml`） |

### 5.2 登录态

**匿名登录**（首次、或刷新失败时）：

```http
POST https://{envId}.api.tcloudbasegateway.com/auth/v1/signin/anonymously
x-device-id: <auth_device_id，首次随机 UUID 并永久保存>
Content-Type: application/json

{}
```
→ `200 {"token_type":"Bearer","access_token":"…","refresh_token":"…","expires_in":7200,"scope":"anonymous","sub":"…"}`

**刷新**（access_token 到期前 5 分钟，或收到 401 时）：

```http
POST https://{envId}.api.tcloudbasegateway.com/auth/v1/token
Content-Type: application/json

{"grant_type":"refresh_token","refresh_token":"<refresh_token>"}
```
→ `200`，返回新的 access_token **和新的 refresh_token（旧的立即作废，必须覆盖保存）**。

**401 处理**：任何数据库请求返回 `401`（实测错误体 `{"code":"INVALID_CREDENTIALS",…}`）→ 刷新一次后重试一次；刷新也失败 → 重新匿名登录后重试一次；仍失败 → 本次同步失败（引擎返回 `ok:false`，下次再试）。并发请求共用一次刷新（Mutex）。

> 账本归属靠**同步码 `ownerId`**，不靠登录用户。重新登录换了匿名用户也不影响读写：读是「所有用户可读」，写只用「新增」。

### 5.3 查询本户全部文档（实现 `CloudCollection.listAll(ownerId)`）

请求前缀：`GET https://{envId}.api.tcloudbasegateway.com/v1/database/instances/(default)/databases/(default)/collections/records/documents`（括号原样保留），头 `Authorization: Bearer <access_token>`。所有查询参数做 URL 编码。

1. 先计数：`?query={"ownerId":"<同步码>"}&count=true` → `{"total":N}`
2. 再分页：`?query={"ownerId":"<同步码>"}&order=[{"field":"updatedAt","direction":"asc"},{"field":"_id","direction":"asc"}]&offset=<o>&limit=100` → `{"offset":o,"limit":100,"list":[…]}`
   - `o` 从 0 起，每次 **+100**（按请求页长推进，不按返回条数），直到 `o ≥ N`；某页返回空列表也继续推进到 `N`，不提前退出（小程序 v0.8.4 就栽在「返回条数少就以为拉完了」上）。
   - 可以每批 5 页并发。
   - **按 `_id` 去重后返回**，顺序 = 首次出现顺序。同一趟同步上传的文档 `updatedAt` 完全相同，必须带 `_id` 次序键 + 去重，否则跨页可能重复（引擎会误以为云端多一笔而重复入账）或漏拉。
3. 返回前把每个文档做 EJSON 解码（§5.5）。

### 5.4 新增一条（实现 `CloudCollection.add(doc)`）

```http
POST …/collections/records/documents
Authorization: Bearer <access_token>
Content-Type: application/json

{"data":[ <doc> ]}
```
→ `201 {"insertedIds":["8cda0ccf6ae9ab450000bad156a997e6"]}`，返回第一个 id；失败返回 `null`（引擎据此不计数、下次补传）。引擎是一条一条 add 的，**不要擅自改成批量**（失败语义会变）。云端会自动加 `_id` 和 `_openid`，安卓不要自己写这两个字段。

### 5.5 EJSON 解码（云端返回强制 Strict EJSON）

实测三种真实形态，解码器都要吃：

| 写入方 | 实测返回样例 |
|---|---|
| 小程序（wx.cloud 全部存成双精度） | `"amount":{"$numberDouble":"12.5"}`、`"updatedAt":{"$numberDouble":"1.790056990507E+12"}`（**科学计数法**） |
| 电脑端（整数存成 Int/Long） | `"amount":{"$numberInt":"25"}`、`"updatedAt":{"$numberLong":"1790056665029"}` |
| HTTP API 写入（安卓将来的样子） | `"amount":{"$numberDouble":"12.5"}`、`"createdAt":{"$numberLong":"1793698628000"}` |

规则：递归遍历；`{"$numberInt":s}` / `{"$numberLong":s}` / `{"$numberDouble":s}` → 数字（`$numberDouble` 可能是 `"Infinity"`、`"-Infinity"`、`"NaN"` 或科学计数法）；`{"$oid":s}` → 字符串 `s`（`_id` 目前实测是 32 位十六进制普通字符串，但要兼容 ObjectId）；`{"$date":…}` → 毫秒数；其余原样。解码后交给引擎的是「和 JS 里一样」的普通 JSON。时间戳类字段（`updatedAt`/`createdAt`）用到时转 Long（`toDouble().toLong()`）。

### 5.6 编码（安卓写云端）

发普通 JSON（Relaxed EJSON）：`amount` 发 Double（如 `25.0`、`12.5`），`updatedAt`/`createdAt` 发 Long 整数，其余字符串/布尔原样。实测服务端会把整数存成 Long、小数存成 Double——与现有两端的文档并存，三端都读得了。

### 5.7 连通性自检（云同步弹窗打开时调用，对应小程序 `testCloud`）

做一次真实计数查询：成功 →「已连接云环境 ✓」；失败 →「读写云端失败：<错误信息>（数据仅存本机，联网后会自动补传）」。

### 5.8 联调清理

开发联调**只用新生成的测试同步码**，绝不用真实用户的码。测试插入的文档可由创建者删除（实测）：
`DELETE …/collections/records/documents/<_id>` → `{"deleted":1}`。联调测试结束必须删干净（按测试同步码 count 回 0）。

### 6.3 去重键与「JS 数字转字符串」（最容易踩的坑）

`recordKey` 里的金额是 JS 的 `${amount}`：`25` 而不是 `25.0`，`0.30000000000000004` 原样，`1.1e+125` 带加号。Kotlin 的 `Double.toString()` 会出 `25.0`、`1.1E125`，**直接用就对不上账**。参考实现：

```kotlin
/** 复刻 ECMAScript Number::toString（金额专用；金标准 amountToKeyString 验收） */
fun jsNumberToString(v: Double): String {
    if (v.isNaN()) return "NaN"
    if (v.isInfinite()) return if (v > 0) "Infinity" else "-Infinity"
    if (v == 0.0) return "0"
    if (v < 0) return "-" + jsNumberToString(-v)
    // 快路径：合法金额（≤2 位小数、远小于上限）——十进制两位小数的最近 double，JS 最短表示就是它本身
    if (v < 1e13) {
        val cents = (v * 100).roundToLong()
        if (cents / 100.0 == v) return BigDecimal.valueOf(cents, 2).stripTrailingZeros().toPlainString()
    }
    // 通用路径（历史脏数据）：取能原样还原这个 double 的最短十进制数字串（1~17 位逐个试），再按 ECMAScript 规则排版。
    // 不能用 Double.toString 取数字：JDK 18 及更早不保证最短（实测 JDK 17 把 6.785272955894471E18 多打一位），安卓同类实现也不能指望
    val exact = BigDecimal(v)
    var bd = exact
    for (p in 1..17) {
        val c = exact.round(MathContext(p, RoundingMode.HALF_EVEN))
        if (c.toDouble() == v) { bd = c; break }
    }
    bd = bd.stripTrailingZeros()
    val digits = bd.unscaledValue().toString()
    val k = digits.length
    val n = k - bd.scale()              // 值 = 0.digits × 10^n
    return when {
        n in k..21 -> digits + "0".repeat(n - k)
        n in 1..21 -> digits.substring(0, n) + "." + digits.substring(n)
        n in -5..0 -> "0." + "0".repeat(-n) + digits
        else -> {
            val e = n - 1
            (if (k == 1) digits else "${digits[0]}." + digits.substring(1)) + "e" + (if (e >= 0) "+" else "-") + kotlin.math.abs(e)
        }
    }
}
```

> 已在 JVM（JDK 17）上用同一算法对照 JS 真值跑过 60,018 个用例（金标准金额 + 随机合法金额 + 浮点尾巴 + 1e-30~1e30 任意量级），全部一致。

`parseRecordKey`：按 `|` 切，必须正好 4 段，金额段用 JS `Number()` 语义解析（`"abc"` → 失败，`"1e+21"` → 1e21）。

### 6.4 `runSync` 步骤（概要，细节以源码为准）

0. 校验同步码；`listAll` 拉本户全部文档，按种类分组。
0a. 登记对端注销凭条额度（跳过 `source ∈ {本机 source} ∪ legacySources` 的凭条，§6.6）。
0b. 计算注销核销量（**时间戳感知**：凭条只能核销 `updatedAt` 早于自己的账单/凭证/撤销），得出有效计数 `effRec/effTomb/effRev`。
0c. 按差额消费注销额度：本地同键行数超出 `effRec` 的部分物理删除，先删回收站行、再删存活行。
1. 上传本机待传注销凭条（pid 已在云端的跳过），成功后清队列并立刻计入核销。
2. 补传账单：本键本地总行数（存活+已删）超出 `effRec` 的差额。
3. 补传删除凭证：配额 = 已删数 D + 累计恢复数 V，超出 `effTomb` 的差额；补传撤销凭条：V 超出 `effRev` 的差额。
4. 补拉账单：`effRec` 超出本地总行数的差额（不设时间窗）。
5. 按净删除数跟随标删/复活（净删 = 凭证 − 撤销，含本轮刚上传的）。
6. 待办、周期账单各跑一次 LWW 实体同步。
7. `store.set(lastSyncKey(ownerId), now.toString())`，返回 `{ok, pushed, pulled}`；任何异常 → `{ok:false, pushed:0, pulled:0, error}`。

### 6.5 本机适配器语义（Repository 实现，必须与 `storage.ts` 行为一致）

| 依赖 | 语义 |

| `addLocal(records)` | 逐条写入；`id` 已存在就跳过（防同一云端记录重复入账）；返回实际新增数 |

### 6.6 设备来源 `source`

- 安卓 `source = "android:" + device_tag`（`device_tag` = `newOwnerId()` 的前 8 位，首次生成后永久保存，清除数据后重新生成）。
- `legacySources = emptyList()`（安卓没有升级前历史）。
- 原因：引擎会跳过 `source` 等于自己的注销凭条。同一户的两台手机如果共用一个名字，A 手机彻底删除的账 B 手机永远不跟删，还会把它补传回云端（小程序 v0.9.6 已修，回归场景㉒）。

### 6.7 SyncManager（调度）

- `syncNow(force: Boolean)`：同一时刻只跑一趟。正在跑时：非强制 → 直接等这趟的结果；强制 → 排队「这趟跑完再补跑一趟」（多次强制合并成一趟）。非强制且距上次完成 < 30 秒 → 直接返回 `ok, 0, 0`。（与 `storage.ts syncNow` v0.9.6 一致）
- `pushSoon()`：每次本地写（记账/删除/恢复/编辑/彻底删除/待办与周期账单的增删改/完成）后调用，在应用级协程作用域里 `syncNow(true)`，**不等待、不阻塞界面**，失败静默（下次同步补传）。
- 触发点：应用冷启动（非强制）；首页、账单页 `ON_RESUME`（非强制）；下拉刷新（强制）；加入同步码、换环境（强制并等待结果）。
- 首页进页：先同步，**同步结束后**（不论成败）再执行到期周期账单（§7.2），防止电脑/手机为同一期各记一笔。
- 同步拉到变化后无需手动刷新：Room Flow 自动推到界面。
- 同步结束后重排一次本机提醒（§10，待办可能被别的端改了）。

## 7. 业务规则

### 7.1 金额（`money.ts` 全量移植到 `core/Money.kt`）

函数：`MAX_AMOUNT=999999999.99`、`AMOUNT_INPUT_MAX_LENGTH=13`、`isValidAmount`、`sumAmounts`、`sanitizeAmountInput`、`parseAmountInput`、`formatMoney(val, decimals=2)`、`formatMoneyExact`、`isSuspiciousAmount`。逻辑逐行照搬，Kotlin 特别注意：

| JS 行为 | Kotlin 正确写法 | 错误写法 |
|---|---|---|
| `x.toFixed(d)`（按 double 精确值四舍五入：`1.005→"1.00"`、`0.005→"0.01"`） | `BigDecimal(x).setScale(d, RoundingMode.HALF_UP).toPlainString()`（用 **`BigDecimal(Double)` 构造**） | `BigDecimal.valueOf(x)`、`String.format` |
| `Math.round(x)`（0.5 向正无穷，**结果仍是 double**，天文数字脏数据不会溢出） | `fun jsRound(x: Double): Double = if (x.isNaN() \|\| x.isInfinite() \|\| abs(x) >= 4.503599627370496E15) x else Math.round(x).toDouble()`；`sumAmounts` 的「分」累加器也用 Double（与 JS 完全同值） | `kotlin.math.round()`（银行家舍入）；用 Long 累加（1.1e125 这类历史脏值会溢出成乱数） |
| 正则 `\s`（含全角空格等 Unicode 空白） | 加 `(?U)` 或显式列出 `\u00A0\u3000` 等 | 默认 `\s` 只认 ASCII |
| `Number(s)`（`"1."`→1，`".5"`→0.5，`"1e5"`→100000，`"abc"`/`"12d"`→NaN） | 先用 `^[+-]?(\d+\.?\d*\|\.\d+)([eE][+-]?\d+)?$` 或 `^[+-]?Infinity$` 筛过再 `toDouble()`，不匹配当 NaN（JS 另认 `0x10` 等进制写法，在 `parseAmountInput` 里结局同为「金额格式不正确」，不必复刻） | 直接 `toDoubleOrNull()`（它会接受 Java 独有的 `12d`、`1f` 写法） |
| `formatMoney` 里 `Number(x.toFixed(d))` 再 `toFixed(d)` 的两次舍入 | 原样两次 | 合并成一次 |

金标准 `golden-vectors.json`（16 组，全部由线上 TS 源码实时算出；JSON 里 `NaN`/`Infinity` 写成字符串）：`amountToKeyString`、`parseRecordKey`、`formatMoney`、`formatMoneyExact`、`parseAmountInput`、`sanitizeAmountInput`、`sumAmounts`、`isValidAmount`、`isSuspiciousAmount`、`advanceDate`、`normalizeOwnerId`、`formatOwnerId`、`isValidOwnerId`、`docLabel`、`cloudToLocal`、`localToCloud`。`GoldenVectorsTest` 逐组逐条断言。

界面约定（同小程序）：汇总类（首页卡片、统计）用 `formatMoney`（自动 万/亿），明细类（账单行）用 `formatMoneyExact`；符号 `+`/`-` 与 `¥` 由界面自己拼。

### 7.2 日期与周期（`dates.ts`）

- `localDateStr()`：本机时区 `YYYY-MM-DD`。**绝不**用 UTC（中国 0~8 点会算成昨天）。用 `java.time.LocalDate.now()`。
- `advanceDate(date, cycle)`：日/周加 1/7 天；月/年**月末对齐**（1/31 + 1 月 = 2/28，闰年 2/29；2/29 + 1 年 = 次年 2/28）；未知周期（含 `once`）原样返回。用 `LocalDate.plusMonths/plusYears` 天然就是这个语义，但必须过 `advanceDate` 金标准。
- 快进到今天之后：`next = advance(d)`，`while (next <= today && guard++ < 2000) { prev = next; next = advance(next); if (next == prev) break }`。
- **周期账单自动执行**（`checkAndExecuteDueBills`）：对每张 `!deleted && isActive && nextDate <= today` 的账单——若 `lastExecutedFor == nextDate`（另一端已记过本期）：只快进日期；否则记一笔（日期=今天、备注 `[周期] <note>`、分类名先补全），回执 `lastExecutedFor = 原 nextDate`，`nextDate` 快进到今天之后；都刷新 `updatedAt`。**账单行与回执在同一个 Room 事务里写**，之后 `pushSoon()` 一次。返回本次记账列表，界面提示「已自动记录 N 笔周期账单」。
- **周期账单手动「立即记录」**（`executeRecurringBill`）：同一事务里记一笔（备注 = 原 note，不加前缀）+ `lastExecutedFor = nextDate` + `nextDate = advanceDate(nextDate)`（只推一个周期）。
- **完成待办**（`completeTodo`）：今天已在 `completedDates` 里 → 忽略；否则加入今天；有金额且有一二级分类 → 同事务记一笔支出（备注 `[待办] <title>` + 有 note 时 ` · <note>`）；`once` → `isActive=false`，其它 → `nextDate = advanceDate(nextDate)`（只推一个周期）。

| `education` 教育学习 | course 培训课程、book 书籍资料、exam 考试报名、stationery 文具用品 |
| `social` 人情往来 | gift 红包礼品、treat 请客吃饭、wedding 婚丧嫁娶、donate 捐款慈善 |
| `finance` 金融保险 | insurance 保险缴费、invest 投资理财、loan 贷款还款、fee 手续费 |
| `pet` 宠物 | pet_food 宠物食品、pet_medical 宠物医疗、pet_supply 宠物用品、pet_beauty 美容洗护、pet_boarding 寄养服务、pet_other 其他宠物 |
| `other` 其他杂项 | express 快递邮寄、misc 其他 |

- 合并分类 = 默认表 + 自定义分类（自定义小类追加到对应大类末尾；新大类追加到表尾）。
- 自定义小类 key：`<大类key>_<毫秒>`；新大类 key：`custom_<毫秒>`，其第一个小类 key：`custom_<毫秒>_<毫秒+1>`。默认分类不可删，自定义可删（已记的账保留原名字）。
- `fillCatNames(item)`：有 `categoryKey`，且一级或二级名为空时，按合并分类表补全；查不到用 key 本身（二级查不到且 key 为空用 `''`）。用在：应用云端实体快照、周期账单记账、待办完成记账。
- 云端拉回的账单带自己的分类名，原样显示，不用补。

### 7.4 账单读写语义（`storage.ts`）

- **排序**（全局统一）：日期倒序；同日按「提交时刻」倒序，提交时刻 = `createdAt`，没有时退用 `id` 转数字，`cloud_` 开头转不了取 0。
- **记一笔**：写本地（id/createdAt = 新毫秒 id）→ `pushSoon()`。保存**不等待网络**（小程序 v0.9.6 修过：旧版保存要等同步跑完，弱网卡住且能连点出重复账）。
- **删除**：`deleted=1` → `pushSoon()`。
- **恢复**：`deleted=0`、`revive_count+1` → `pushSoon()`。
- **编辑**：旧行 `deleted=1`；插入新行 = 旧行全部字段 + 修改项，新 id，`createdAt` 沿用旧行（旧行无则用旧 id 数字），`deleted=0`，照片沿用 → `pushSoon()`。
- **彻底删除**（只对回收站行）：注销凭条入队 `{pid, targetKey: recordKey(行), cancelRec:1, cancelTomb:1+V, cancelRev:V, label}`（V = revive_count），物理删行，清理孤儿照片 → `pushSoon()`。
- **撤销**（记一笔后 5 秒内）：= 删除刚记的那笔（进回收站并推删除凭证），表单回填刚才的内容。

### 7.5 统计口径（只统计存活行）

- 月合计：`date` 以 `YYYY-MM` 开头且类型匹配的金额，分为单位累加。
- 分类汇总：按一级（`categoryKey`/`categoryName`）或二级（`subcategoryKey`/`subcategoryName`，名为空退一级名），分累加，金额倒序。
- 每日趋势：按 `date` 分累加，日期升序。
- 近 6 个月：以所选月为终点往前 5 个月（含跨年）。

### 7.6 预算

只存本机，仅「当月」显示。百分比 `round(支出/预算×100)`；状态：支出 > 预算 = 超支，≥80% = 预警，否则正常；剩余天数 = 当月天数 − 今天 + 1；日均可花 = 剩余>0 ? 剩余/剩余天数 : 0。输入 0 = 清除预算，其它走 `parseAmountInput`。

### 7.7 待办到期统计（`getDueSummary`）

只看 `isActive` 且今天未完成的：`nextDate == 今天` 计「今天到期」，`< 今天` 计「已逾期」。

### 7.8 同步码

12 位，字符集 `ABCDEFGHJKLMNPQRSTVWXYZ023456789`（去掉易混的 I/O/U/1），首次随机生成。显示每 4 位一杠（`ABCD-EFGH-JKMN`）。加入别人的码：去掉非字母数字、转大写，≥8 位才合法。换新码：重新随机生成（旧账本仍在云端，只是不再拉取）。

### 7.9 清除本机所有数据

确认框：标题「清除本机所有数据？」，内容「将清空本机的账单、待办、周期账单、预算、自定义分类和小票照片，并换一个新同步码。云端账本不会删除，记下原同步码 XXXX-XXXX-XXXX，以后在「云同步」里加入即可找回」，确认按钮红色。确认后清空 Room 全部表 + DataStore（含同步码、设备标识、登录态）+ `filesDir/photos`，取消全部提醒。

## 9. 视觉规范（「靛」风格，参照 `miniapp/src/app.scss`）

约束：无渐变、无阴影、无装饰 emoji、字重最高 Medium(500)、靠留白和 1px 细线分层。尺寸换算：小程序 `rpx ÷ 2 = dp`（如卡片圆角 20rpx → 10dp，页面边距 28rpx → 14dp，正文 28rpx → 14sp）。

## 10. 本机到期提醒

- **每日汇总**：每天 08:00 一条通知（与小程序云函数同时刻）。内容按 §7.7 统计「今天到期 + 已逾期」的待办：0 个不发；1 个 → 标题 = 待办标题，正文 = 备注或「今天有件事该做啦」；多个 → 标题「今天 N 个待办到期」，正文「还有：A、B、C…」（标题按到期日升序拼接，截断到一行）。
- **定时待办**：设了 `time` 的活跃待办，在 `nextDate` 当天该时间单独提醒一条（标题 = 待办标题）。
- 点击通知 → 打开 App 并进入待办页。通知渠道「到期提醒」。
- 调度：`AlarmManager.setExactAndAllowWhileIdle`；Android 12+ 若 `canScheduleExactAlarms()` 为 false，退回 `setAndAllowWhileIdle`（可能晚到）并在待办页提示（§8.7-3）。每次触发后排下一次。
- 重排时机：应用启动、待办任何增删改/完成、同步拉到待办变化、开机（`RECEIVE_BOOT_COMPLETED`）、改系统时间/时区（`TIME_SET`、`TIMEZONE_CHANGED`）、清除数据（全部取消）。
- Android 13+ 首次需要申请 `POST_NOTIFICATIONS`（在待办页点「开启到期提醒」时申请，不要一打开 App 就弹）。
- 国产手机省电策略可能杀后台导致不准时：待办页给出「去设置」引导（应用详情页），不做各厂商专门适配。
- 周期账单**不在后台自动记账**，仍和小程序一样「打开 App 进首页、同步完成后」才执行（防双端各记一笔）。

## 11. 导出 Excel

- 入口：账单页「导出Excel」，导出**当前筛选结果**；无数据 Toast「无数据可导出」。
- 文件：`计序_YYYY-MM-DD.xlsx`，工作表名「账单」，列 = 日期、类型（支出/收入）、一级分类、二级分类、金额（数值单元格）、记录人、备注；行序同列表。
- 生成到 `cacheDir/exports/`，弹底部选项：「发送给微信好友 / 其他应用」（FileProvider + `ACTION_SEND`，MIME `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`）、「保存到手机」（`ACTION_CREATE_DOCUMENT` 让用户选位置）。失败 Toast「导出失败」。

## 12. 小票照片

- 「拍小票」：`ActivityResultContracts.TakePicture`，目标 = FileProvider 指向 `filesDir/photos/<毫秒>.jpg`；「选照片」：`PickVisualMedia`（仅图片），复制进同目录。**不声明** CAMERA / 存储权限。
- 落盘前压缩：长边 ≤ 1600px、JPEG 质量 80。失败 Toast「照片保存失败」。
- 只存本机、不上云。物理删除账单行（彻底删除、对端注销凭条消费）后，若该照片路径已不被任何行引用就删文件（编辑会让新旧两行共用一张照片，必须按引用判断）。

## 13. 权限清单

`INTERNET`、`POST_NOTIFICATIONS`、`SCHEDULE_EXACT_ALARM`、`RECEIVE_BOOT_COMPLETED`。不要其它权限。

## 14. 打包签名与分发

1. 生成签名密钥（只做一次）：`keytool -genkeypair -v -keystore jixu-release.jks -alias jixu -keyalg RSA -keysize 2048 -validity 36500`。`jks` 文件和两个密码**由负责人离线备份两份**，绝不提交进 git（`keystore.properties` 与 `*.jks` 加入 `.gitignore`）。
2. `app/build.gradle.kts` 从 `keystore.properties` 读签名配置；release 开启 R8 压缩（kotlinx.serialization 自带混淆规则，检查一次 release 包同步功能正常）。
3. 版本：`versionName` 与产品版本对齐（如 `1.0.0`），`versionCode` 每发一版 +1（只增不减，否则无法覆盖安装）。
4. 打包：`./gradlew assembleRelease`，产物重命名为 `计序-v1.0.0.apk`。
5. 分发：微信发文件 / 网盘。经验提示：部分安卓微信不能直接点开 APK，需在聊天里「用其他应用打开」或保存后用文件管理器安装；首次安装需允许「安装未知来源应用」。
6. 升级：新版本同包名、同签名、更大的 versionCode，直接覆盖安装，本机数据保留。
7. 从小程序迁移到安卓：在安卓「云同步」里输入小程序显示的同步码 → 账单、待办、周期账单全部拉回；预算、自定义分类、小票照片需在安卓上重新设置（它们本来就只存本机）。
