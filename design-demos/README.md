# 计序 · 三个界面方向（可交互 Demo）

同一份真实账本数据（631 笔、11 大类 51 小类、2026-06 ~ 2026-11），三种完全不同气质的界面。
**不是图片**：每个 demo 都能切月份、记账、搜索、筛选、删除、撤销、切暗色。

## 怎么看

- 总览对比：双击打开 `design-demos/index.html`（可切「手机 / 电脑」「首页 / 记一笔 / 账单 / 统计」「白天 / 夜间」）
- 单独体验：
  - A 朱印 · 账簿 → `design-demos/a-ledger/index.html`
  - B 夜航 · 仪表 → `design-demos/b-instrument/index.html`
  - C 色谱 · 日子 → `design-demos/c-spectrum/index.html`
- 直接拖进 Chrome 即可，无需安装、无需联网（字体已内嵌）。

## 三个方向

| | A 朱印 · 账簿 | B 夜航 · 仪表 | C 色谱 · 日子 |
|---|---|---|---|
| 一句话 | 排版考究的纸质账本 | 精密仪表盘 | 每月一条独一无二的色带 |
| 气质 | 安静、有文化感 | 专业、专注、科技感 | 温暖、活泼、手感好 |
| 主色 | 纸白 + 墨黑 + 朱红（≤5% 面积） | 近黑 + 荧光绿（信号色） | 暖白 + 11 分类专属色 |
| 数字 | 大号衬线（Instrument Serif） | 等宽（Martian Mono） | 粗体无衬线（Bricolage） |
| 中文标题 | 思源宋体（按需子集 105 字 / 106 KB） | 系统黑体 | 系统黑体 |
| 桌面 | 书脊式竖排导航 + 双页展开 | 左侧图标轨 + 顶栏状态 + 模块面板 | 悬浮胶囊导航 + bento 卡片 |
| 手机 | 纸页 + 底部纸签栏 | 模块堆叠 + 圆形「记」键 | 悬浮胶囊栏 + 大号「+」 |
| 预算表达 | 一把「尺」：每日刻度 + 匀速幽灵线 | 270° 表盘：指针 + 匀速刻度 | 果冻罐：按分类色堆叠 |
| 记账成功的瞬间 | 朱印「已记」盖下 → 这一行写进账本 | 扫描线「发送」→ 指示灯亮 → 记录滑入日志 | 颜色块飞向色谱 → 那一段变长 |

## 交互清单（三版一致）

- **首页**：月份切换、本月支出、收入 / 结余 / 笔数、预算（已用 / 剩余可花 / 日均可花 / 匀速对比）、分类前三、月度报告、今日账目、最近记录、到期待办（完成 / 记账）、下一笔周期账单、同步状态
- **记一笔**：支出/收入、金额（手机自定义键盘支持 `+` 连加；电脑直接键盘输入）、11 大类 + 小类 + 常用、日期 / 时间 / 记账人 / 备注 / 小票，保存 → 各自的方向性动效 + 5 秒撤销
- **账单**：月份 / 收支 / 分类筛选，关键词搜索（命中高亮），按天分组 + 当日小计，行内金额区分收支，删除与撤销，桌面悬停 / 手机左滑出现编辑删除，批量多选（A/B），渐进渲染（首屏 40 行，滚动续载）
- **统计**：月份切换、一级/二级分类、分类占比（三种原创图形）、排行点分类下钻到账单、每日趋势（未到的日子明确留白）、近六月收支对比
- **更多**：周期账单（开关 / 立即记录）、待办（完成）、分类管理、回收站、导出、备份、云同步、暗色模式、快捷键

快捷键：`Ctrl+Shift+N` 随时记一笔；`0–9 . +` 输入金额；`Enter` 保存；`Esc` 清空；账单页 `/` 搜索；`Ctrl+1..` 无（demo 用左侧导航）。

## 性能（真机口径：手机视口 + 4 倍 CPU 降速）

| 指标 | A 朱印 | B 夜航 | C 色谱 | 目标 |
|---|---|---|---|---|
| 首屏内容（FCP） | 124 ms | 436 ms | 516 ms | ≤ 1 s |
| 可交互（字体+入场完成） | 1122 ms | 1137 ms | 1187 ms | ≤ 1.2 s |
| 切页掉帧（>25 ms 的帧） | 0–1 帧 / 4 次切页 | 1 帧 / 4 次 | 1 帧 / 4 次 | ≤ 2 |
| 切页最差帧 | 24–67 ms | 36–97 ms | 49–79 ms | ≤ 100 ms（4× 降速下） |
| 首页滚动掉帧 | 0 | 0 | 0 | 0 |
| 控制台错误 | 0 | 0 | 0 | 0 |
| 体积（JS / CSS） | 67 / 60 KB | 69 / 44 KB | 87 / 71 KB | ≤ 100 / 80 KB |

约束（为了能一比一移植到小程序和 Compose）：只动 `transform` / `opacity`；不用 canvas / WebGL；不用大面积 backdrop-filter；图表全部可由普通盒子或 Compose Canvas 画出。

## 自检评分（迭代 3 轮后）

| 维度 | A | B | C | 说明 |
|---|---|---|---|---|
| 排版 | 9 | 8.5 | 8.5 | A 的中西文混排与字号阶梯最讲究；B 的等宽数字列对齐最稳 |
| 留白 | 9 | 8 | 8.5 | A 的页边与分栏留白最从容 |
| 视觉层级 | 8.5 | 9 | 8.5 | B 的「一个数一个读数」最不容易看错 |
| 色彩 | 9 | 8.5 | 9 | A 的朱红克制；C 的 11 色在 oklch 同明度下统一 |
| 动效 | 8.5 | 8.5 | 9 | C 的颜色飞入与色带生长最有记忆点 |
| 微交互 | 9 | 8.5 | 8.5 | A 的印章 + 书写感；B 的按键压感 |
| 响应式 | 8.5 | 8 | 8.5 | 三版都做到 360 / 390 / 768 / 1280 / 1440 无横向溢出 |
| 原创性 | 9.5 | 8.5 | 9.5 | A 的「预算尺 + 印章」；C 的「色谱 + 颜色日历」 |

```
    ├── probe.cjs       在页面里取任意量（node tools/probe.cjs <demo> <route> <宽> "<表达式>"）

    └── build_fonts.py  重新生成 shared/fonts.css（改 display-chars.txt 后跑）
```

## 选定方向之后

界面代码会按这个 demo 一比一移植到三端（Electron/React、Taro 小程序、Compose），
同时按 `PerfAudit` 的结论做流畅性修复（桌面端每次写库重写整库、窗口白屏、大包同步加载；
小程序每次读全部月度分片、每次同步拉全量；安卓切页重查整表、冷启动主题闪）。
